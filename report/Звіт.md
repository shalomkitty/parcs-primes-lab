## 1. Мета роботи

Ознайомитися з технологією ПАРКС, розгорнути розподілену систему PARCS-Python на Google Cloud Compute Engine і дослідити продуктивність послідовного та паралельного алгоритмів за різної кількості воркерів.

## 2. Постановка задачі

Знайти кількість простих чисел на відрізку `[2, N]`. Для вимірювань обрано `N = 2 000 000`. Простим є натуральне число, більше за одиницю, що має рівно два натуральні дільники.

## 3. Програмні засоби та архітектура

- **Мова:** Python (сумісна з Python 2.7 у навчальній реалізації PARCS-Python).
- **PARCS-Python:** master приймає задачу, розподіляє піддіапазони між воркерами та збирає результати через Pyro4.
- **Google Cloud Compute Engine:** одна VM `e2-standard-4` з 4 vCPU.
- **Docker:** один контейнер master, від одного до чотирьох контейнерів worker у приватній мережі Docker на тій самій VM.
- **Доступ:** localhost через SSH-тунель, без відкритих зовнішніх портів PARCS.

Схема: `Браузер → SSH-тунель → Master → Worker 1 / Worker 2 / Worker 3 / Worker 4 → Master`.

## 4. Опис послідовного алгоритму

Master перевіряє кожне число від 2 до N. Число є простим, якщо не ділиться на жоден цілий дільник від 2 до квадратного кореня числа. Парні числа (крім 2) пропускаються; для непарних перевіряються лише непарні дільники. Кількість знайдених простих чисел накопичується в лічильнику.

## 5. Опис паралельного алгоритму

Множина чисел від 2 до N ділиться на приблизно рівні неперетинні інтервали. Master надсилає кожен інтервал одному воркеру, викликаючи віддалений метод `count_primes(bounds)`. Воркери працюють незалежно. Master очікує результати й підсумовує їх. Правильність контролюється порівнянням з послідовним результатом.

## 6. Методика експерименту

На однакових вхідних даних N = 2 000 000 запускається обчислення з 1, 2 та 4 воркерами. Для кожної конфігурації записуються час послідовного обчислення `T₁`, час паралельного обчислення `Tₚ`, прискорення `S = T₁ / Tₚ` та ефективність `E = S / p`. Для меншого впливу випадкових коливань рекомендовано три повтори з усередненням результатів. Час запуску контейнерів не враховується.

## 7. Перевірка правильності

Локальні модульні тести (без реального PARCS) перевірили:

1. Відомі значення кількості простих чисел: π(2)=1, π(10)=4, π(100)=25, π(1000)=168.
2. Відсутність пропусків і повторів при розбитті діапазону на 1, 2 і 4 частини.
3. Роботу Solver із чотирма тестовими воркерами та запис `prime_count=168` для N=1000.

**Статус локальних тестів:** 3/3 успішно. Для `N = 2 000 000` очікуване значення `π(N) = 148933`; після хмарного запуску потрібно звірити з цим значенням результат кожної конфігурації.

## 9. Висновки

Реалізовано послідовний алгоритм та паралельний алгоритм із поділом діапазону чисел на незалежні підзадачі. Локальні тести підтвердили правильність реалізації та процедури збирання результату. Фактичний висновок про вплив числа воркерів на швидкодію можна зробити **лише після виконання вимірювань на Google Cloud**. Прискорення може бути нелінійним через накладні витрати на мережеву взаємодію, запуск задач і спільне використання ресурсів однієї VM.
